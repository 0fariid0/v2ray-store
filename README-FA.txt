به‌روزرسانی بررسی رسیدهای تکراری — ۹۰ روز

فایل‌های لازم:
1. config.php — جایگزین فایل ریشهٔ ربات
2. bot.php — جایگزین فایل ریشهٔ ربات
3. settings/receiptSimilarity.php — فایل جدید در پوشهٔ settings

قبل از جایگزینی، از فایل‌های فعلی و دیتابیس بکاپ بگیرید. هر سه فایل را با حفظ همین مسیرها منتقل کنید؛ بهتر است ابتدا فایل جدید settings/receiptSimilarity.php و سپس دو فایل ریشه جایگزین شوند. baseInfo.php، اطلاعات اتصال، توکن و دیتابیس را جایگزین نکنید.

تغییرات:
- بررسی تمام حساب‌ها و هر دو گروه مشتری، در بازهٔ ثابت ۹۰ روز گذشته؛ شامل مرز روز نود و بدون وابستگی به زمان اجرای پاک‌سازی.
- شناسایی فایل یکسان با شناسهٔ تلگرام و SHA-256؛ حفظ سازگاری با اثرانگشت‌های تصویری نسخهٔ قبلی.
- مقایسهٔ چند خط متوالی تصویر برای تشخیص احتمالی رسیدهای دارای برش، تغییر اندازه یا فشرده‌سازی. قطعات بسیار کوچک، برش سنگین از وسط نوشته‌ها، عکس کج و تغییرات شدید ممکن است تشخیص داده نشوند. رسیدهای هم‌قالب نیز ممکن است هشدار شباهت بگیرند؛ هشدار اثبات تکراری بودن تراکنش بانکی نیست.
- هشدار مدیر، نوع تطبیق، سفارش فعلی و آیدی صاحب رسید قبلی را نشان می‌دهد. طول پیام محدود شده و اگر پیام قدیمی حذف شده باشد، هشدار روی رسید جدید یا مستقل ارسال می‌شود.
- خطای دریافت تصویر یا بررسی دیتابیس، رسید مشتری را رد نمی‌کند؛ وضعیت ناقص به مدیر اعلام می‌شود. منطق تأیید/رد سفارش قبلی حفظ شده است؛ هشدار، جای بررسی دستی پرداخت را نمی‌گیرد.
- خاموش بودن بررسی رسیدها حفظ می‌شود و در این حالت پردازش تصویر انجام نمی‌شود.

نیازمندی و فعال‌سازی:
در تنظیمات ربات ← بررسی فیش‌های تکراری، گزینهٔ بررسی را روشن نگه دارید. بازه در همین صفحه ۹۰ روز و وضعیت GD نشان داده می‌شود.
تشخیص برش و شباهت به افزونهٔ GD در PHP ربات نیاز دارد. GD باید هم برای PHP وب و هم PHP خط فرمانِ کران فعال باشد. بدون آن، شناسایی فایل یکسان تا حد امکان ادامه دارد، ولی بررسی برش انجام نمی‌شود. cURL و mysqli همان نیازمندی‌های قبلی ربات هستند. سرویس OCR یا کلید API جدید لازم نیست.
جداول و ایندکس‌های موردنیاز به‌صورت خودکار ساخته می‌شوند؛ کاربر دیتابیس باید مجوز CREATE و مجوزهای قبلی ربات را داشته باشد. SQL دستی یا حذف جدول لازم نیست.

رسیدهای قبل از نصب:
اثر انگشت‌های موجود برای تطبیق دقیق فوراً استفاده می‌شوند. اثر انگشت جدیدِ رسیدهای قابل‌دریافتِ ۹۰ روز اخیر به‌تدریج از روی receipt_file_id ذخیره‌شده در pays بازسازی می‌شود؛ هر بار اجرای کران فعلی settings/reportGroupBackup.php، حداکثر ۳ رسید. تاریخ اصلی رسید حفظ می‌شود. رسید ناموفق روز بعد دوباره امتحان می‌شود.
برای این بازسازی، کران فعلی گزارش ربات باید فعال باشد. تا پایان بازسازی، تشخیص برش برای همهٔ رسیدهای قبلی آماده نیست. اگر عکس یا شناسهٔ قدیمی ذخیره نشده/دیگر قابل‌دریافت نباشد، نمی‌توان اثر انگشت تصویری آن را از هش قبلی بازسازی کرد. فایل تصویری دانلودشده پس از پردازش حذف می‌شود؛ فقط اثرانگشت‌ها نگهداری می‌شوند.

اعتبارسنجی محلی:
- ۲۴ سناریوی تصویر ساختگی فارسی/لاتین: برش، تغییر اندازه، JPEG، تصویر خالی، قطعهٔ کوچک و تراکنش‌های متفاوت با قالب یکسان.
- ۶۰ بررسی رفتاری: حساب متفاوت، مرز ۹۰ روز، سفارش یکسان، خطا، دانلود محدود، حذف فایل موقت، خاموش بودن قابلیت، قفل و بازسازی سابقه.
- ۱۲ آزمون روی MariaDB واقعی برای ساخت جدول، کوئری‌های تولیدی، پنجرهٔ زمانی، ایندکس تصویری، پاک‌سازی وابسته و بازسازی سابقه.
- بررسی نحوی هر سه فایل PHP؛ ۶۷ آزمون منو/مسدودسازی و ۱۵ آزمون نمایش حجم قبلی نیز پاس شدند.
تست زنده روی سرور، دیتابیس یا رسیدهای واقعی شما انجام نشده است. پس از نصب، یک رسید آزمایشی را در دو سفارش و دو حساب متفاوت امتحان کنید و هشدار مدیر را ببینید.

این بسته بر پایهٔ آخرین اصلاح علامت * مشتریان جدید آماده شده است؛ تغییرات امروز فقط به بررسی رسید مربوط است.
